# 跨节点发行策略核对

迁移 `051_app_release_policy` 为每个应用包保存当前发行策略摘要、递增 revision 和不可变的变更
回执。服务每次处理 `GET /v1/app/releases/latest` 时，在核对账号／手机／组织的同一数据库快照
中核对本机目录摘要；不匹配返回 503 `update.unavailable`，没有候选下载元数据。
因此撤回、缩小灰度或更改支持窗口后，旧节点不能继续按旧目录推荐发行。

这项检查只影响更新元数据接口，不撤销已下载或安装的 APK，不中断会话或替代设备授权。
在策略提交前已完成准入的在途响应仍可能稍后到达；客户端继续执行独立的下载、哈希和签名核验。
本批仅开发 Go 服务与本地夹具，不涉及 Android APP 实现。

## 摘要与初次启用

`dsh-app-release-policy/v1` 摘要是 SHA-256，输入为 UTF-8 域名、一个 NUL 字节及 RFC 8785
规范化后的完整有效目录。下载来源、组织列表按字符串排序，publications 按版本号降序；
JSON 排版、字段顺序与集合重排不改变摘要。包名、版本窗口、全部 publication、URL、说明、
灰度及目标组织都参与摘要，空目录也有独立摘要。

应用迁移后，首次启用该包的受信任配置在启动事务中登记制品身份及 revision 1 策略，
之后启动只核对，不修改当前策略。冲突启动失败，不将发行功能静默降级为未配置。
升级时需先核对可信配置并升级／隔离所有发行查询节点，旧二进制不执行新检查；
不能把首次登记的任意抢先节点当作可信配置来源。迁移不会从旧占位表推导当前发布政策。

## 管理命令

使用服务账号和既有受控 PostgreSQL 配置执行，不向手机开放写入 API：

```sh
# 仅解析受保护候选文件，离线输出 format、package_name 和 policy_sha256。
remote app-releases describe --catalog-file /受控目录/releases-next.json

# 读取当前 ready 数据库代次下该包的摘要和 revision；未登记时 configured=false。
# REMOTE_DATABASE_URL、REMOTE_DATABASE_EPOCH 由部署环境提供。
remote app-releases status --package-name cn.edu.ustc.tokenworks

# expected-sha256 来自核对过的当前 status；operation-id 每个新变更唯一。
remote app-releases replace \
  --catalog-file /受控目录/releases-next.json \
  --operation-id <新的UUID> \
  --expected-sha256 <当前策略摘要>
```

`describe` 不打开数据库或联络发行地址，不输出 URL、组织列表或发行说明。
其他命令明确要求 `REMOTE_DATABASE_EPOCH`，不会猜测恢复代次。候选继续经过原有私有文件和完整目录
校验。`replace` 在事务中核对当前摘要、不可变制品登记与代次，写入新的策略、revision、变更回执及
一次审计；任何步骤失败整体回滚。不能用它改变已经固定的 APK 文件或签名身份。

响应或 stdout 丢失时，保持原 operation UUID、原 expected 摘要和完全相同的有效候选策略重试，
返回原回执，不再次应用。后续已提交其他策略时，核对旧操作也不会恢复旧策略。
同 operation UUID 换内容、旧摘要竞争或无变化的新操作被拒绝；回执的 revision 不能证明它仍是当前
策略，应另查 status。所有候选制品及策略必须预先完成审核，本命令不签名、上传、发布或部署文件。

变更会立即令使用其他摘要的节点在下一次更新查询中失败关闭，可在业务服务仍运行时执行。
把同一候选配置受控分发并逐节点重启后，这些节点才恢复更新查询。需要避免更新接口短暂 503 时，
应在入口暂停该接口后协调变更和重启；核心业务无需随之停机。未配置发行功能的节点仍不提供该路由。
重新采用历史目录也必须作为新的显式变更；完全相同的策略重新成为当前状态时，仍持有该相同目录的
节点可再次通过摘要核对。该摘要约束有效策略，不是每次变更独立的客户端令牌。

## 审计、恢复与回退

数据库触发器要求策略更新具有匹配的保留回执。回执不可修改、删除或 truncate；
已有策略／回执时 down 迁移拒绝删除历史。初次登记及变更审计仅保存包名、摘要、revision、代次和
操作 UUID，不保存 URL、目标组织和说明。审计失败不允许策略先行生效。

恢复隔离时拒绝管理写入和服务准入。应用迁移 052 后，正常释放仍需在新代次
[重新核对发行策略](app-release-recovery.md)，未变化目录显式 confirm，变化目录显式 replace；
确认前旧目录不开放更新查询，status 的 current 为 false。
旧代次的操作回执不能用于新代次修改状态。恢复旧备份仍需与外部可信当前配置核对，
本机制不是独立防回滚账本，也不能自动恢复备份后丢失的登记或撤回决定。

## 定向证据

本批集中验证有效目录摘要、集合重排、策略变更／撤回、旧节点准入、历史操作重试、并发 CAS、
审计回滚、不可变回执及禁止破坏性回退。两个实际 HTTPS handler 使用 JWT／DPoP、登记手机及同一个
隔离 PostgreSQL：撤回前均返回发行，变更后旧目录均返回 503，加载空目录的新节点返回 `release:null`，
原节点的账号查询仍可用。这里的节点是同一测试进程中的独立 HTTP 服务，不是两台生产进程。
管理 CLI 使用真实服务二进制核对 stdout 丢失后的回执，既有生产启动夹具继续检查冲突配置不开放监听器。
没有运行全量、Android、Windows／Wine、真机或大负载测试，也未使用学校配置或实际发布制品。
