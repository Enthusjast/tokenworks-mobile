# JWKS 缓存与轮换

Go 中转和 Host 资源 JWT 验证器从可信配置指定的 JWKS 地址取公钥。请求明确要求
`Cache-Control: no-cache` 和 `Accept-Encoding: identity`，不能从未验证 JWT 指定密钥来源。
学校 IdP 尚未配置，本批验证使用本地 HTTP issuer 夹具。

## 新鲜度

两端默认最多复用 60 秒，并取响应 `max-age` 与 60 秒的较小值。Go 以前默认五分钟、上限一小时，
且会把短 TTL 提升到一分钟；现在不再延长发行端声明的 TTL。响应年龄取 `Date` 表示的年龄与
`Age + 请求耗时` 的较大者，再扣除读取和解析响应耗时。未来的 `Date` 不延长缓存寿命。

`max-age=0`、`no-cache`、`no-store`、重复／无效 `max-age`、重复／无效 `Age` 或 `Date`，
以及时钟倒退，都会禁止本次响应的后续复用。支持带引号的十进制 `max-age`，拒绝负数、
小数、符号和超出 uint64 的值；`Date` 要求规范 IMF-fixdate。超长 HTTP 年龄不会溢出并延长 TTL。
两端共用 [新鲜度用例](../contracts/security/jwks-cache.json)。

零 TTL 仍允许刚取回并校验过的公钥用于当前查询，下次查询必须重新取回；不表示拒绝当前响应。
Go 可保留过期公钥表用于区分已知 ID 和未知 ID，但不会用其授权；这不提供内存擦除保证。

## 换钥和失败处理

- 新 key ID 可触发刷新，未知 ID 的主动刷新至少间隔五秒；零 TTL 也不允许随机 ID 持续刷新。
- 同一 ID 换钥只在缓存到期后生效，签名错误本身不触发额外刷新。发行端应使用新 key ID，
  并按签发令牌的有效期安排旧键退出。移除旧键不会让已缓存验证器立即感知撤销。
- 未过期缓存遇到失败的未知 ID 刷新时，仍可验证原有键；缓存过期后刷新失败，不回退到旧键。
- Go 允许旧公钥表中的已知 ID 在未知 ID 冷却期内重新获取。Host 不保留零 TTL 公钥表，
  无缓存且遇到未知 ID 时，冷却期内其他查询也可能暂时失败关闭。
- 缓存建立后墙钟倒退，Go 丢弃该缓存并拒绝当前查询；Host 重新获取，不将旧缓存判为有效。

## 密钥与响应边界

两端均限制响应为 128 KiB、最多 32 个键，支持 RS256（RSA 2048–8192 位）和 ES256（P-256）。
RSA 位数按实际模数判断，2047 位密钥即使占用 256 字节也必须拒绝。RSA 整数拒绝前导零、
偶数模数和不合法指数；公钥参数使用规范无填充 base64url，P-256 坐标必须为曲线上有效点。

存在的 `kid`／`alg` 必须具有正确类型；有 ID 的键限制为 256 个 UTF-8 字节并禁止 Unicode
控制字符。拒绝重复 key ID、私钥／远程密钥成员和不兼容的签名用途。Go 的公共 JWK 解析器
也用于设备证明；有效的无 `kid`／`alg` P-256 公钥仍可使用。
