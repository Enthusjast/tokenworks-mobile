# Go Host 文件流的独立取消

`Handoffs.Open` 的租约到期和 Host 连接退出现在通过独立取消路径结束读取，
不等待正在进行的 `CheckFileRead` 数据库复核。原有每 500 毫秒复核、单次一秒上限、
五秒租约和一百毫秒余量保持不变；旧租约计时器已经启动时不能通过晚返回的复核重新激活。
硬到期继续由原 handoff context 限制。

## 准入和读取

消费 ticket 后，租约余量不足或 Host 生命周期已经结束时不开始对象请求。
等待响应头期间取消，或对象服务晚返回 body 时，控制器关闭 body 并拒绝交付；
没有 body 的成功返回也不作为合法流。ticket 已经消费的事实不会因此回滚，需要正常的新 handoff。

每次 Read 在底层读取前后检查 context 和原 Host 生命周期。即使不响应取消的 reader 稍后返回
了字节，已取消流也返回零字节与错误，不把这块数据交给 HTTP writer。
取消回调和显式 Close 共用一次底层关闭，重复／并发 Close 不会再次操作 body。

## 慢响应写出

Host 文件 HTTP handler 将流的取消绑定到响应 write deadline。
对象读取已经返回但客户端卡在 response.Write 时，租约、撤权或 Host 退出仍能打断等待；
写出下一块之前也重新检查取消，不能用新的常规写期限覆盖已经失效的权限。
原每块 30 秒写期限没有延长，也不改变内容长度、摘要或 Host 端原生准入要求。
已经进入网络的字节无法撤回，控制面仍负责每次权限复核和后续新请求的独立授权。

## 定向验证

小型 Go race 夹具覆盖响应头和 body 阶段：元数据复核阻塞时，900 毫秒的测试仓库租约到期
或 Host 退出仍独立取消。短租约来自夹具返回的真实截止值，不缩短生产五秒上限。
另验证晚返回字节被丢弃、body 只关闭一次、失效准入不调用存储，以及无效存储返回的清理。
HTTP writer 夹具在 Write 内阻塞，Host 退出后通过实际 ResponseController deadline 路径结束。

本批集中执行六项顶层 Go race 用例及六个子场景，全部通过，无跳过。
这些用例检查 Go 流和 HTTP 生命周期，不替代真实学校身份、生产对象服务或容量验收。
没有运行全量回归、Host 全链路、Android、Windows／Wine、真机、大负载或厂商推送测试。
