# Host 终态对账与本地收尾

绑定被管理员拒绝、被取消或过期后，可以显式调用
`HostTerminalEnrollmentWorkflow.cleanupTerminal(signal)` 收尾。
这条路径只清理经过认证并精确匹配的恢复记录和绑定定位文件，不删除安装私钥、
密钥库引用、命令 journal 或会话数据，也不会准备新的申请或重新请求本机批准。
现有 `cleanup(signal)` 继续用于已批准绑定的恢复文件清理，不删除有效绑定定位文件。

```ts
const result = await workflow.cleanupTerminal(signal)
if (result) {
  // result.terminal.state 仅可能为 denied / expired / cancelled。
  // recoveryRemoved / bindingRemoved 表示原匹配文件是否被删除。
}
```

## 服务端的不可再激活事实

先应用 migration `049_enrollment_terminal_checks`，再使用
`POST /v1/enrollments/host-terminal`，严格 JSON body 仅含原业务 `request_id`。
该接口只接受允许的 Host OAuth client、当前有效的安装所有者账号及组织成员关系，
并要求 DPoP 安装公钥与原安装一致。手机 client、其他账号、错误安装密钥、
未知 request ID、query selector 或额外 body 字段不能取得可用证明。
它不返回配对码、access token、私钥、用户 subject 或组织目录信息。

服务端按原 request ID 查找并锁定申请及主机、安装和 runtime。
未过期 pending/user_confirmed 或任何 approved 申请返回冲突，不能据此清理。
如果已有批准事务持锁，收尾等待该事务结束；若它已批准，返回冲突或要求重试，
不会把等待期间的未知结果当作过期。

过期 pending 在同一事务中写为 expired；既有 denied/expired/cancelled 保留终态。
随后退休该未批准 runtime，只有没有未撤销 sibling 时才退休共享安装及其剩余凭据/challenge；
没有未撤销安装的 pending Host 才退休。有效 sibling 的权限保持原样。
事务保存不可变的终态、安装所有者、公钥指纹和观察时间，再写一次审计和 runtime 失效 outbox。
终态证据返回前已提交；数据库触发器阻止旧节点修改该申请或删除证据。
同参数重试对账同一观察时间，不重复退休、审计或事件。迁移也拒绝删除已有证据。

## 两个本地文件如何处理

恢复路径和绑定路径在整个在线核对、文件校验和删除期间保持当前 JavaScript 运行域互斥。
受保护文件按既有当前用户/私有目录、无链接、描述符及 inode 校验规则读取和删除。
服务端响应必须匹配本地账号/origin/客户端/scopes/安装密钥，以及 request、组织、主机、
安装、runtime、profile、期限和完整工作区映射。
有恢复文件时还核对其别名、版本和工作区引用，并保持整份认证字节在核对期间不变；
存在版本 2 定位记录时，另外核对其中保存的完整原始恢复摘要，不一致时不删除。
没有定位文件时不声称核对过服务端从未保存的配对码，而是依赖原请求身份、完整非秘密输入和不可再激活事实。
旧版定位记录与恢复文件配对时仍需显式人工处理，
不会绕过缺失的完整恢复摘要。

旧恢复文件只作为惰性元数据读取，超过本机十分钟意图期限也不会被恢复成可发送的配对尝试。
创建响应丢失、尚无绑定定位文件时，仍可用原 request ID 和完整输入向服务端对账，
但不会额外调用 create。原请求不存在或权限不可用不能证明它从未提交，文件会保留。
待确认、已批准、403、断线、取消、不匹配及损坏响应都不会被当作终态证明。
终态对象采用独立验证标记，不能用作已批准绑定来启动 Relay。

先删除并同步恢复文件，再删除定位文件。若两次删除之间进程停止或 I/O 失败，
定位文件仍可用于显式重试，即使恢复文件已经不在也能完成收尾。
两个文件无法用一次文件系统事务删除；取消或错误可能发生在某次删除已完成之后，
不能把异常当作“什么都没做”。跨进程共享路径仍需发行端协调所有权，
本接口不把文件不存在当作服务端没有旧申请的证明。

正常安装有其他 profile 时，可在原安装下以全新申请重新登记；
如果安装已退休，则需发行端显式配置新安装身份并完成资源登录和登记。
收尾不会轮换或清除旧私钥，也不会自动迁移其他绑定。
SSO 账号失效或已失去组织成员关系时，在线收尾会拒绝；现有显式 `discard` 仍须按可信操作流程使用。

## 验证边界

定向夹具覆盖拒绝、取消和真实数据库过期锁定、批准竞争、不可变证据、幂等观察，
以及有界 Host HTTP 协议、本地过期记录、创建响应丢失、两文件删除中断、
上下文/文件替换、互斥、取消及终态不能冒充批准。
这些是本地 Go / PostgreSQL / Host 夹具证据，生产密钥轮换、学校身份配置和跨进程发行策略仍需单独落实。

本批集中运行选定 Go race 用例、46 个相关 Host/契约用例和 TypeScript 检查，均通过；
复核后只补跑收尾来源校验相关的 6 个用例与类型检查。没有运行全量测试、Android、
Windows / Wine、真机或负载测试。
