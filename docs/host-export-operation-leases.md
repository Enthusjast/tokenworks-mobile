# Host 导出操作的期限与关闭

`RelayExports` 与文件交接共用 `FileOperationLease`：墙钟和单调时钟共同限制五秒租约、
最初五分钟硬期限及一百毫秒余量。续租必须在原许可仍有效时到达；观察到到期或时钟倒退后，
旧作业不会因为时钟恢复或迟到回复再次变成可用。硬期限始终按最初接受的预算限制，不随续租推迟。

续租等待仍为 2.5 秒，但现在处理 `file.export.renewed` 时也核对墙钟／单调时钟期限，
而非仅依靠 250 毫秒清理 timer。超过等待期限即终结原等待集合中的作业，取消来源，
后续旧 upload 帧不会重新读取或开始 PUT。没有改动公开帧、签名用途、服务端权限或到期策略。

## 关闭与并发

registry 已关闭或报告清理失败时，不接受新的目录／媒体解析请求，原作业的 current 检查也会失败。
来源在异步调用中晚返回，不会发布新的目录、manifest 或上传成功结果。已经提交给传输层的帧仍受
连接 writer 和 Go 对端的当前准入校验，不能据此承诺取消已进入网络的字节。

导出作业和媒体解析共用八项 Host 并发预算与 request ID 空间；不会只在媒体入口计算合并数量，
又从导出入口额外接收八个。取消但仍未结束的任务继续占用预算并保留其 request ID，实际结束后才释放；
一个作业的阶段重叠不会被当成两个独立名额。媒体解析同样使用共享的不可复活期限检查，并保留原短租约取消 timer。
正常续租后仍按原不透明 source ID、原 operation ID 和固定字节执行一次匿名 PUT，然后走现有 committed 流程。

## 定向验证

本地 npm DSH `0.2.1-rc.5` Loader 和真实固定来源验证：续租回复晚到时关闭实际文件描述符，
旧 upload 不发 PUT；时钟倒退后不能恢复；registry 关闭后不再列出来源或发送晚返回结果。
另外用八个未进行正文 I/O 的媒体验证／目录等待检查共享预算和取消后计数，并验证正常续租后的精确字节 PUT 与原操作确认。

首批 21 项相关用例通过；补齐取消中任务计数后，仅复测 6 项导出用例与类型检查，均通过，无跳过。
测试使用内部可注入时钟，不调整系统时间或缩短生产期限。匿名 PUT 使用内存 transport 夹具核对完整字节，
不连接真实对象服务。没有运行全量回归、Go、Android、Windows／Wine、真机、大负载或学校身份联调。
