# Host 暂存 receipt 的关闭与竞争

`NativeFileRegistry` 同时跟踪已暂存 receipt、当前交接尝试和实际仍未结束的异步工作。
关闭 registry 会同步停止新暂存、取消在途信号并退休已发布 receipt；它不会在同一个对象上重新开放。
异步上传若在关闭或被新交接替换之后才返回，结果不会进入映射，返回的 receipt 会单独回收。
插件的新运行代次仍创建新的 registry，不能借旧对象恢复权限。

## 并发与容量

32 项预算包含已暂存映射和仍未结束的尝试。取消或替换只撤销其权限，实际工作结束前仍占预算，
防止不响应取消的服务靠反复替换绕过上限。Relay 原有最多两个并行下载保持不变。
失败、完成或晚返回后才释放对应在途预算；明确失效或已被原生消费的映射在查询／下一次准入时清理。
预算耗尽拒绝新准入，不吞掉错误、不改用不受控来源。

每次尝试在 await 之前保存文件元数据及交接 ID 的快照，异步等待期间修改原输入不能更换文件 ID、
用户、设备、名称或目标映射。每个等待阶段和每块来源数据都核对关闭状态、当前尝试身份及原授权。
最终发布还核对原生 Session 中 receipt 确实存在。原生服务已经存好文件但尚未返回时，取消依然不能
让晚返回的 receipt 成为可发送消息的权限。

## 确认、回收与断线

Relay 发送 staged 确认和清理时携带精确 handoff ID。旧交接的确认不能确认新映射，旧交接的结束也
不能退休新 receipt。内部消息完成后的按 file ID 清理继续用于回收当前命令拥有的映射。
原始调用信号取消会同步撤销其映射并尝试回收，不依赖后续轮询或手机再次查询。

registry 关闭后，即使旧传输仍在等待其他模块收尾，文件 peer 也不会开始新的 GET。
HTTP reader 在原生准入尚未消费来源就失败时也会取消和解锁；常规来源流和错误路径共享同一收尾。
回收失败不恢复映射；底层服务若永远不返回或不响应取消，registry 不能强制结束该服务，
但保持容量占用并拒绝重新发布。这里不承诺删除 DSH 已持久附件对象或已经入队的消息。

## 本地验证

小型夹具使用精确锁定 npm DSH `0.2.1-rc.5` Loader，暂停在真实附件存储完成、上传结果返回之前，
验证关闭和同 file ID 替换；晚返回的旧 receipt 被退休，新 receipt 保持独立。
另覆盖原输入变更、调用信号取消、旧 staged ack、新交接清理隔离，以及 32 个未读取正文的在途
元数据尝试达到预算、取消不提前归还预算、实际结束后可继续暂存。

集中验证包含上述用例、相关文件交接／消息／图片准入和 TypeScript 检查，没有全量回归、
Go、Android、Windows／Wine、真机、大负载或真实学校身份测试。
