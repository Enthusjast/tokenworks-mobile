# Signed approval authorization leases

The Go control-plane store can now produce short signed authorization proofs from an already accepted decision. TypeScript independently verifies the authority and phone signatures, then keeps ephemeral evidence for the synchronous native final guard. This implements an internal provider and host verifier/cache; the [optional server HTTPS/WSS transport](approval-protocol.md) now connects the server operations. The [normal native owner](approval-native.md) now supplies callback/body/guard ownership and offers the capability when provisioned. Real IdP configuration, host key provisioning and Android signing remain separate work.

The lease payload uses domain `dsh-mobile-ustc/approval-authorization/v1`, audience `dsh-approval-host/v1`, protocol 1, and an HTTPS issuer fixed by deployment. It binds host/installation/runtime/epoch/session/approval/execution UUIDs, the exact host connection ID, a fresh lease UUID, owner `approval.decide`, context and canonical decision digests, policy, user/device/key/grant versions, registered approval-key thumbprint and public key, assurance profile, original authentication time and issue/expiry times. Public JWKs have exactly `kty`, `crv`, `x` and `y`. Full arguments, native call IDs, resource facts and nonce are absent from the lease.

Compact JWS is ES256, protected header exactly `{alg,kid,typ}`, with type `dsh-approval-authorization+jws` and key ID `dsh-approval-authority/<configured identifier>`. Payload/header are JCS UTF-8; base64url is canonical/unpadded and signatures use 64-byte JOSE encoding. Key URLs, caller keys, duplicate/case-aliased fields, extra headers, private JWK material and DER signatures are rejected. A lease cannot be used as a phone decision or moved to another connection.

An authority trust anchor is configured independently of the peer delivering a proof. It pins issuer, key ID, P-256 public key/thumbprint, active state and an explicit validity interval. Signature verification fetches no URL. Key rotation/revocation requires replacing the configured trust set and closing affected caches. `approval.NewAuthorizationSigner` copies the configured private key into its own process memory, exposes only a copied public descriptor, and enforces its issuer/key validity. The optional entrypoint loads an explicitly configured protected PEM secret file; OS/HSM storage and automatic key-distribution trust are not supplied. Fixture keys are never production anchors.

Both the policy JSON and PEM now use the [shared protected-configuration reader](trusted-service-configuration.md): current service-account ownership, private regular files without hardlinks, no-follow/nonblocking open, metadata rechecks, and literal struct-field names. Invalid configured policy fails startup; no permissive approval fallback is enabled.

The offline [authority description and rotation workflow](approval-authority-rotation.md) exports only public anchors and policy metadata with a deterministic JCS digest. Host parsing requires an independently configured digest; neither the document's own hash nor a peer/JWS header establishes trust. Describing a scheduled/historical key never enables it for runtime signing, and the workflow does not automatically replace live keys or caches.

`store.NewApprovalLeaseProvider` joins the transactional approval controller with a signer. `Issue` accepts the server-authenticated current host connection/key and transient actual context. It locks the current runtime/session, accepted approval, active user/device/membership and owner grant. The device approval/proof thumbprints and key version must still equal the recorded decision, as must the grant version. Current action and session/workspace scope are checked again. A regrant, refreshed phone token or another device cannot refresh the original decision's evidence. The stored phone proof is independently verified and must still match its canonical digest. A rejected decision may receive a proof of its recorded authority, but the host journal still denies execution for that decision.

Lease lifetime is positive and at most three seconds. Expiry is clipped to request, signed decision, original access token, original authentication-age limit, current grant, authority key and host heartbeat deadlines. Every date is UTC with millisecond precision; clipping rounds down. There is no future-issuance or expiry grace. Minting still uses the shared phone decision's 30-second issue-freshness rule. Once that window closes, this provider refuses further issuance; it does not silently rewrite or re-sign the phone decision.

The provider prepares audit/outbox metadata in the same transaction as its authoritative reads, signs while holding the relevant locks, and returns the proof only after COMMIT and a final expiry check. Any database/signing failure returns no proof. `approval.authorization.prepare` and `approval.authorization.prepared` describe preparation, not native execution or successful delivery. They contain IDs, hashes, versions and times; neither signed proof nor execution body enters these event payloads. A proof prepared near an expiry can still expire before delivery and must be rejected by its receiver. The control worker now acknowledges this preparation topic without treating it as an execution/delivery claim.

`verifyApprovalLease` / `approval.VerifyAuthorization` verify the pinned authority proof and its key/time window, exact context/connection, embedded registered phone key, phone signature and canonical decision digest. Only then is a plain internal `ApprovalAuthorization` constructed. Its assurance profile and authentication age must match the request, and lease expiry cannot exceed request/decision/authority/authentication deadlines. Pure verification grants no repeatable execution permission.

`ApprovalLeaseCache` is created for one host/installation/runtime/epoch/connection and one to eight pinned authority keys. It bounds concurrent verification and retained entries to 64, copies all accepted values, removes expired entries, and supplies synchronous evidence only for the same context/decision digest. Its `authorization` method is suitable for the journal's admission and final-guard authorizers. It never fetches authority or extends an expiry. Close clears all entries and fences in-flight results; a backwards or invalid clock closes it. The normal plugin closes the cache on connection/profile disposal.

Cache time is anchored when the connection cache is created. Each comparison uses the later of wall time and its monotonic projection.
A wall freeze or an unobserved backward step therefore cannot stretch the signed three-second window. Forward wall steps consume
lifetime immediately and rebase the projection, so freezing afterward cannot wait for an older projection to catch up. Fractional
monotonic time is retained; conservative integer rounding occurs only when checking the signed dates. Verification completion,
guard lookup and retries all use the same clock anchor, including a delayed first proof or a repeated copy of an expired proof.
Invalid, reversed or throwing clocks close the cache; restoring the clock cannot reopen it. The optional fourth constructor
callback supplies a monotonic clock for controlled tests; normal integration uses `performance.now()`. No system clock is changed.

Focused clock regressions cover freeze, unseen backward adjustment, forward-then-freeze, fractional reads, delayed verification/first proof,
and invalid monotonic values. They can explicitly select an offline-verified Host bundle through the existing bundle test variables;
pure `verifyApprovalLease` remains a one-time verifier, while repeatable guard authority stays in the cache.

The [365b025 package record](host-package-verification-365b025.md) adds a native body-boundary regression:
after approval admission, it freezes the test process wall callback and synchronously blocks beyond the lease deadline,
preventing expiry timers from running. The previous package executes the body and fails the zero-call assertion;
the fixed package denies body entry. Normal allowed execution remains covered by the same focused native fixture.

Negotiated `approval.invalidation.v1` adds actor-scoped negative authority facts on the authenticated host connection. A device tombstone rejects that device for the connection's lifetime; a user's grant-version floor rejects older proofs without rejecting equal/newer versions or another actor. Floors only increase. At most 1024 combined actor entries are retained; overflow closes authority instead of evicting a fence. Admission checks these facts after both signatures verify, so an in-flight proof cannot restore revoked authority. Synchronous authorization checks apply the same fence. A valid but fenced proof cancels its native pending request, while invalid signatures still cannot consume pending state. Three-second expiry remains the fallback bound during event loss, and fresh issuance independently rechecks authoritative database state. Production account/key provisioning hooks still need verification. The journal independently compares grant versions, checks live context/resource facts, persists one-use consumption and refuses replay after restart.

The shared schema now includes leases. `contracts/security/approval-leases.json` contains public-only Go/Node interoperability vectors, including valid allow/reject and malformed/boundary cases. Regenerate explicitly with `tsx tools/generate-approval-leases.ts` (`REMOTE_TEST_GO` overrides the Go binary). Fresh private keys exist only in generator process memory, so regeneration intentionally changes public keys/signatures. Both language suites verify all vectors. Go tests must use `-count=1` because shared fixtures live outside the Go module.

`npm run verify` includes host cache/journal tests and real npm DSH 0.2.1-rc.2 final-guard tests: a valid signed lease executes the protected fixture once; revoked/altered/expired leases do not. The native adapter uses a synthetic local authority, not a production school identity or mobile network flow. `npm run test:remote-dsh` also runs PostgreSQL provider coverage with race detection before the production Go + DSH session/question regression: exact original authority, expiry clipping, failed audit/outbox, changed connection/context and expired-token nonrenewal are tested in disposable databases. The server transport is implemented and separately tested with signed fixture peers; normal plugin wiring now has real Bash/CLI evidence; Android and production identity/provisioning still need acceptance.

The private [approval metrics](approval-observability.md) distinguish committed
preparation, declared bounded lifetime and the post-commit availability check.
A preparation that expires during commit remains a preparation fact and returns
no proof. No metric is a lease-consumption receipt or refreshes authentication.
