# Host 导出源的关闭等待与容量

`FileExportRegistry` 为每个创建中的来源预留一个容量名额，并持续拥有其固定文件描述符，
直到关闭 Promise 实际结束。准备摘要、可用条目、被释放／清理的来源及读取收尾共用 32 项预算，
准备摘要的并发上限仍为两个。删除不透明 export ID 只停止该身份的使用，不代表句柄已经关闭。

所有关闭都通过按来源去重的任务追踪处理。显式 release、自动过期／撤权清理、读取结束，以及
未能发布的来源使用同一关闭路径。关闭完成后才归还名额；关闭尚未结束时不会因条目已从映射移除
而继续打开无限多个文件。来源版本不匹配的失败也经过相同的所有权和收尾处理。

## 插件关闭与错误

registry 关闭时先同步停止新准入、清空公开映射并取消原生命周期，然后等待仍在创建和所有已拥有
来源的关闭任务。已经从映射移除、但仍在异步关闭的来源也必须等待；等待期间新取得的来源由其准备
任务收尾，关闭流程继续检查直到全部结束。重复 close 复用同一结果。

若来源的关闭 Promise 报告错误，不会阻止其他来源的关闭或卡住准备计数。错误只以 `file.export_unavailable` 报告，
不包含路径或底层异常；此前发生过的关闭失败不会让后续 close 假报成功，新导出准入也会失败关闭。
这不意味着能强制终止不响应取消的文件系统调用，或能撤回之前已送入对象服务的字节。

## 定向验证

Linux 本地夹具打开真实 `PinnedExportSource`，在真正关闭文件描述符之前暂停：
release 删除条目后，registry.close 仍须等待，`/proc/self/fd` 中的句柄在放行关闭后归零。
另用 32 个小文件句柄验证清理中的来源继续占预算，实际关闭后才能继续准入；这不是文件吞吐或负载测试。
关闭异常夹具验证固定错误、准备计数收尾和重复关闭不能报告成功。

集中运行 17 项相关 DSH 原生会话附件／图片、导出目录、匿名上传及清理用例，全部通过，无跳过；
TypeScript 检查通过。
没有运行全量回归、Go、Android、Windows／Wine、真机、大负载或真实对象服务测试。
