# Go 服务的受保护配置输入

审批策略 `REMOTE_APPROVAL_POLICY_FILE` 及其 PEM 签名密钥，现在与文件、推送、
Relay、限流、身份同步和恢复等部署入口共用私有文件读取规则。
策略路径为空时，审批能力仍保持禁用；明确配置却无效时启动失败，不回退到默认策略。

## 文件身份与读取

当前 Unix 实现要求文件为运行账号所有、仅所有者可访问的非空普通文件，
且硬链接数必须为一。每种输入继续使用原有字节上限；审批策略最多 512 KiB，
审批私钥最多 16 KiB。例如，部署时可为服务账号准备只读或可读写的私有文件：

```sh
chmod 600 /受控目录/approvals.json /受控目录/authority.pem
```

文件必须由实际服务/CLI 运行账号拥有；不要通过共享硬链接发布私钥或策略。
Unix 打开时使用 no-follow 和 nonblock 标志，防止 lstat 后叶子被换成符号链接或 FIFO，
并在读取前后及返回前核对描述符/路径的 inode、大小、权限和修改时间。
读取长度必须等于原文件大小；读取、重新校验或关闭失败时清除已读缓冲并返回固定错误。
这样不会把半写入、被替换或暴露权限的文件当成新配置。

部署端仍需保护配置目录、全部祖先目录、发布来源和运行账号；这个读取器没有递归核验祖先，
也不能防御已控制当前服务账号的进程。使用受控临时普通文件完整写入、设置所有权/权限，
再原子替换正式文件；与读取重叠的替换可能被拒绝，应在发布完成后重新加载，不能放宽校验。
不提供平台等价校验时，受保护输入失败关闭。本批只在 Linux 验证，未运行 Windows 或 Wine。

## JSON 字段契约

共享 JSON 入口保留重复字段、无效 Unicode、未知字段和尾随数据的拒绝规则。
在正常类型解析之外，增加结构体字段的精确 JSON 名称核验：

- `policy` 与 `Policy`、`private_key_file` 与 `Private_Key_File` 不等价。
- 同时提供 `version` 和 `Version` 不能覆盖策略。
- 数组内的映射项以及 map 内的结构体值也按相同规则检查。
- 明确声明的动态 map 键保持大小写，不会改写加密 key ID 等数据。
- 时间等自定义 JSON 解码器保留其表示约定；业务校验仍由原有加载器执行。
- 允许省略的指针字段仍保留原有 null / omission 语义，例如组织审批策略的 null 不会被写成 false。

这项变化不会改写输入值、策略版本、摘要算法、签名格式或当前授权范围。
旧文件若依赖大小写别名，必须改为公开声明的 JSON 字段名，不能把解析失败当作可降级条件。
错误只报告固定配置类别，不回显文件内容、签名材料、账号或存储秘密。

## 加载与轮换边界

校验发生在进程启动或显式 CLI 加载配置时。正在运行的进程保留已加载配置，
不会因为文件改变而自动更换审批签名器。发行签名、防回滚、可信分发和钥匙库/HSM 管理
仍由部署流程负责；单次文件校验不能证明这些能力。
轮换审批 authority 时，按既有独立信任配置更新 Host trust set、关闭旧缓存并受控重启服务，
不能从收到的 JWS header、key URL 或未经配置的文件自动建立新信任。

## 定向验证

相关用例覆盖有效配置、大小写/Unicode 别名、覆盖式重复命名、嵌套字段、
动态 map 与时间/null 兼容、公开权限、硬链接/符号链接、外部 UID 元数据负例、
元数据变化、替代 inode 和真实 FIFO 无写端时的非阻塞打开。
文件、推送禁用配置、Relay、限流、发布目录及身份 CLI 的相关现有用例也用于兼容检查。
没有运行全量测试、移动端、Windows / Wine、真机或负载测试。

本批集中执行相关 `cmd/remote` Go race 用例通过；审批能力仍需显式配置才开启，
既有有效配置及禁用配置的语义未改写。
