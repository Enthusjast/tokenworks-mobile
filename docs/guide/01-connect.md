# 连接与配对

[项目首页](../../README.md) · [会话与审批](02-sessions.md) · [故障排查](03-troubleshooting.md) · [安全说明](../../SECURITY.md)

## 开始前

- 使用 Android 8.0（API 26）或更高版本，并设置安全锁屏。凭据与离线记录依赖系统安全存储；密钥不可用时不会改为明文保存。
- 电脑运行 dsh `0.2.2` 系列和 TokenWorks Mobile Host 插件；支持合法的预发布版及构建元数据，不接受 `0.2.1`／`0.2.3`。当前原生 API 生成与实际验证基线为 `0.2.2-rc.1`，并非其他发行版已经逐一验收；同次加密握手的 HELLO／READY 仍须精确版本一致。
- 由管理员提供服务器部署配置和可信 CA。TLS 公钥指纹不能替代正常的证书有效期、CA 与主机名验证。

## 两种独立授权

**中继账号授权**决定哪些设备可以通过服务器访问哪些电脑。登录、登记设备，再按电脑上的流程核对并绑定安装与运行实例。网页账号登录本身不等于手机远控设备已登记。

**Host 加密配对**决定这台设备是否持有目标电脑认可的独立密钥。即使中继授权有效，也不能跳过 Host 配对。仅本地配对不会自动获得中继账号、组织或租约权限。

没有中继账号时，可使用应用的独立局域网入口；仍须完成下面的 Host 配对和加密验证。

绑定中继账号的配对，即使实际选择 LAN、P2P 或 TURN，也必须取得当前有效的同一账号授权租约；切换路径不会扩大权限。需要完全独立的本地访问时，应在独立局域网模式由操作员另行批准配对，不能把已有账号绑定记录偷偷改成本地 owner。

## 首次配对

1. 在电脑 dsh 设置的 TokenWorks Mobile 页面生成一次性配对描述符。
2. 通过当面展示、受信文件或其他可信方式取得完整 JSON。描述符包含一次性秘密，不要发到公开群聊、工单或日志。
3. 手机打开主机配对，粘贴二维码中的 JSON 内容，或选择“导入 JSON 文件”。此入口不要求相机权限。
4. 核对 HTTPS 地址、运行时、安装标识、TLS pin、Noise 公钥及主机密钥版本；不能只核对电脑名称。
5. 确认与操作员提供的信息一致，填写设备名称，再选择“验证并安全配对”。

应用先验证 TLS，再发送配对秘密；先安全保存恢复信息，再向电脑提交配对。原生会话、终端与文件流量必须通过 Noise 认证，不存在配对失败后继续使用明文业务接口的选项。

## 配对结果待核对

页面出现“结果未知”不表示电脑没有接受请求。不要重新生成一套凭据反复配对。

- 选择“核对主机并安全保存”：使用已保存的同一套凭据查询，不重发配对写入。
- “重试安全保存”只处理本地安全存储收尾。
- 在主机撤销成功前，不要把“仅忘记本地恢复信息”当作撤销授权。忘记后可能只能请电脑操作员处理残留配对。

## 选择主机和路径

主机管理按安装标识组织运行实例。仅当身份、配对与密钥版本匹配，局域网和中继才可代表同一目标。电脑名称、地址相似或中继广告不足以合并身份。

自动选择只在同一可信目标内寻找可达路径，不会改连另一台电脑。TLS、Noise pin、凭据或授权校验失败会停止连接；不会用另一条路径绕过撤权。网络切换也不会自动重放已派发的写操作。

P2P/TURN 需要电脑操作员明确配置，并由手机用户按账户授权使用。未同意时不进行 ICE 地址收集。启用后，所配置的 STUN/TURN 服务会看到网络地址及连接元数据；这不授予其读取 Noise 正文的能力。关闭此授权会关闭相应连接。

## 更换密钥与移除授权

- **轮换此设备密钥**：先保存新密钥恢复记录，再提交一次轮换。丢失回复时只核对新密钥，不重发或退回旧密钥。
- **电脑轮换主机密钥**：操作员明确确认后撤销旧配对。手机必须重新核对新描述符；不会从中继公告自动接受新公钥。
- **在主机上撤销**：终止该配对的加密访问；确认电脑持久撤销后再清理本地记录。
- **仅从此设备移除**：只删除手机保存的凭据，不会通知电脑撤销。
- **中继设备、授权或安装撤销**：独立于本地配对。设备丢失时，两侧都需要检查，见[安全说明](../../SECURITY.md#设备丢失与撤销)。
