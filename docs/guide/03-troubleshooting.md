# 故障排查

[连接与配对](01-connect.md) · [会话与审批](02-sessions.md) · [安全说明](../../SECURITY.md)

先记录页面上的错误码、目标电脑及操作时间。不要附上配对 JSON、设备令牌、私钥、账号 token、完整聊天或终端输出。截图前遮住这些信息。

## 连接失败

| 页面或错误 | 含义与处理 |
| --- | --- |
| `lan.tls_failed` | CA、主机名、有效期或 TLS pin 未通过。核对操作员提供的证书与完整描述符；不要关闭证书验证。 |
| `lan.identity_mismatch` / `e2e.pin_mismatch` | 实际目标不是已信任身份。停止使用该地址，请操作员核对；不能靠切换路径绕过。 |
| `e2e.repair_required` | 配对版本或主机密钥已不匹配。操作员检查并撤销旧配对，再提供新描述符重新核对。 |
| `e2e.unsupported` | 加密库、ABI、协议或目标能力不支持。使用兼容构建；不存在明文兼容模式。 |
| `e2e.relay_unbound` | 当前配对没有绑定真实中继设备身份。独立 LAN 权限不自动扩展到中继；需操作员明确批准重新配对。 |
| `auth.expired` / `auth.proof_invalid` | 账号凭据或设备证明未通过。先核对系统时间和账号状态，再恢复登录；不要反复发送原业务请求。 |
| `access.denied` / `lan.revoked` | 当前授权被拒绝或已撤销。由授权方核对资源权限，不能尝试另一条路径绕过。 |
| `network.unavailable` | 暂时不可达。核对电脑在线、地址、局域网隔离、防火墙及中继状态；不要因此清空安全凭据。 |

P2P 不可达不表示身份错误。检查是否明确同意地址发现、电脑是否启用 RTC、网络是否允许对应连接。TURN 还需要管理员提供可用服务。中继、STUN 和 TURN 的可用性是不同条件；不能仅凭配置存在或页面展示选项认定路径已建立。

## 配对或密钥轮换待定

保留安全存储中的原恢复记录。配对结果未知时查询同一凭据；设备轮换待定时选择“核对新设备密钥并保存”。两者都不能通过重新生成密钥、自动重发写入或退回旧密钥解决。

安全存储不可用时，先确认设备已解锁、仍设置安全锁屏。系统重置或密钥丢失可能使旧凭据不可恢复；请电脑操作员撤销旧配对后重新配对。不要手工复制另一台手机的私有文件。

## 消息、审批和提问

- **消息显示结果未知**：先看电脑会话，再决定是否显式重试；保留原请求 ID。断线并不证明消息未被接受。
- **审批卡片消失或按钮失效**：请求可能已撤销、结束，或由另一原生 owner 界面回答。重新读取当前状态，不恢复旧按钮。
- **只能查看不能回答**：会话读取权限不等于 owner 回答权限；请授权方核对，不在手机伪造 owner 标记。
- **定时问题已经过期**：只有电脑仍允许的迟到回答可以提交；不要把补答改成另一个无关问题。
- **离线只有旧内容**：缓存只读。恢复可信连接后重新读取；不要把旧缓存状态当作电脑当前状态。

## 终端和文件

- 终端没有输出时，先核对所选终端、会话及连接状态。重新连接不重发历史输入。
- 文件无法预览时，核对类型、大小和当前授权。对不支持的类型使用明确导出，不把它作为可执行网页打开。
- 上传、导出或下载中断时，以页面完成状态为准。未完成的文件不能当作成功结果继续使用；不要将部分文件追加成另一次下载。
- 文件选择器或云端提供器拒绝读取/写入时，重新选择有权限的来源或目标位置；应用不会绕过提供器权限。

## 通知与后台连接

1. 核对应用内通知开关及系统通知权限。
2. 确认管理员启用了推送并配置真实提供方；仅安装 SDK 不代表服务可用。
3. 后台连接需单独启用，并受系统电池、网络和前台服务限制。
4. 点击引用通知后若资源不可读，先恢复当前账户授权；通知不是访问凭据，也不保存正文供离线恢复。

## 向维护者报告

提供客户端与 dsh 版本、Android 版本、路径类型、错误码、动作类型及是否显示“结果未知”。说明问题发生在配对、握手、读取还是写入之后。默认不要提供原始网络包或整个应用目录；它们可能包含身份、内容与秘密。
