## 1. 产品目标与成功标准

### 1.1 优先服务的任务

1. 打开应用后，迅速找到并继续一个已获授权的会话。
2. 阅读电脑上产生的消息、代码和工具结果，保留当前阅读位置。
3. 在手机上发送消息，明确区分排队发送、补充当前任务及离线保存。
4. 及时发现需要人工处理的提问与工具审批，并准确完成核对。
5. 上传会话附件、导出文件，理解检查、接收和保存的进度。
6. 完成电脑绑定、会话创建、设备登记及必要的设置。

日常使用路径优先于设备管理路径。登记成功说明、版本、完整 UUID 和运行环境诊断信息移入适当的详情位置；任务正文、当前状态和下一步操作保持明显。

### 1.2 本轮验收目标

| 编号 | 目标 | 验收口径 |
| --- | --- | --- |
| G01 | 登录完成后，默认进入会话入口 | 已有授权且已取得目录时，首屏直接出现可打开的会话；不先经过账号管理按钮区 |
| G02 | 已展示的会话一次点击打开 | 不再要求点击卡片内部独立的“读取会话”按钮；当前授权复核仍执行 |
| G03 | 普通字号下明显缩小输入区 | 在 360 × 640dp、键盘关闭、无附件及无待处理横幅时，输入组件主体以 100–128dp 为初始目标；系统安全区另计 |
| G04 | 聊天默认突出消息正文 | 标题栏紧凑；健康连接不单独占用大卡片；文件和发送记录不阻挡首屏正文 |
| G05 | 阅读历史不被实时消息打断 | 新消息到达时保留锚点；用户在底部时才跟随新增内容；提供回到底部入口 |
| G06 | 请求状态更容易理解 | 本机保存、中继接收、电脑保存、Agent 入队和执行结果使用可区分的状态 |
| G07 | 审批完整性保持 | 未完整展示并逐页核对全部动作信息时，无法启用“仅本次允许” |
| G08 | 手机基本操作易于触达 | 点击区域至少 48 × 48dp；图标有语义标签；状态同时使用文字与视觉提示 |
| G09 | 大字体和横屏可操作 | 320dp 窄屏及 2.0 字体缩放下，关键内容可滚动阅读，确认、拒绝和返回可到达 |
| G10 | 样例数据可独立验证 | 学校配置、真实模型和推送账号未就绪时，仍可完成本地界面与生命周期验收 |

涉及任务完成速度的验证使用相同数据、设备、构建类型和操作脚本。每轮保存原始记录；没有测量结果时只标记为目标，不能写成性能提升结论。

### 2.2 当前体验问题

- 已登记首页先显示刷新、通知、更新、绑定和退出，访问会话需要滚动或继续进入电脑目录。
- 电脑和会话多用大卡片加多个通栏按钮，同屏可比较的信息偏少。
- 会话名称主要依靠短 UUID；现有目录模型没有任务标题、摘要和完整的未读定义。
- 聊天把返回、退出、主机标题和连接状态放在正文之前；多种操作面板还会继续占用阅读区域。
- 输入区常驻模式按钮、字段标签、辅助说明和通栏发送按钮，键盘关闭时仍较高。
- 审批完整上下文以 JSON 为主要阅读形式，核对成本高，但其完整性和逐页确认机制具有明确业务意义。
- 文件、命令和交互的可靠性说明较多，需要建立“简短状态 + 可展开详情”的呈现层。
- `HomeState` 和页面分支承载多个流程，新增导航时需要防止扩大连接、状态恢复和回调生命周期。

### 2.3 截图基线的使用边界

已有展示截图使用本地样例数据，可用于比较层级、密度和可达性。展示标识条以及为了截图而单独展开的面板不属于正式产品结构，不能据此误判正式应用的页面数量或网络能力。

实施前重新保存基线：会话列表、聊天顶部与底部、离线状态、审批长参数、提问、文件、绑定、创建、通知和更新。每张记录设备尺寸、字体缩放、主题、应用版本和数据场景，不将截图样例写成真实业务事实。

## 3. 范围与交付边界

### 3.1 第一批：使用已有协议交付

- 三个主入口：会话、电脑、设置。
- 统一标题栏、列表项、状态提示、按钮层级和明暗主题。
- 当前电脑目录、会话打开入口和已访问会话的展示优化。
- 聊天阅读、输入区、历史加载、发送记录和会话详情。
- 工具审批的字段化完整阅读与核对。
- 普通提问、计划确认、计时问题和文件操作的收纳。
- 登录登记、绑定、创建及应用更新的流程优化。
- 已知、当前获授权会话内的待处理入口。

第一批不以服务端新增元数据为前置条件。“最近会话”只能展示当前身份下已有可靠来源且通过当前访问核验的记录，并标明索引范围。

### 3.2 后续增强：先完成协议与数据设计

| 增强 | 前置条件 | 未就绪时的行为 |
| --- | --- | --- |
| 全量跨电脑会话聚合 | 受授权约束的目录汇总、分页、排序和限流方案 | 先按电脑分组查询；不为填满首页打开所有会话连接 |
| 任务标题与摘要 | 明确生产者、字段范围、更新语义、长度限制和版本协商 | 使用已核验工作区标签、短 ID 和更新时间；不存在的字段不伪造 |
| 未读提示 | 确定已读游标、持久化位置、同步与撤权语义 | 不把“更新时间变了”直接解释为未读消息数量 |
| 全量待办页 | 不依赖推送通道的最小授权查询接口 | 仅汇总当前已知、已验证资源的引用，并注明非全量 |
| 扫码绑定 | 版本化二维码载荷、解析边界、过期和组织校验 | 保留编号与绑定码输入流程 |
| 批量归档等管理动作 | 明确各会话状态、授权和原请求语义 | 首期只提供单会话显式操作 |

### 3.3 本轮不扩大业务权限

- UI 不增加后台常驻读连接，也不承担集群路由改造。
- 待办不要求用户先开通 FCM 或其他推送通道。
- 不增加模型凭据输入、手机直接执行命令或任意路径浏览能力。
- 不改变消息、创建、答案和审批的原请求身份、签名及重试规则。
- 不把缓存可读改成无条件离线授权。
- 不因界面调整升级整体依赖、替换数据库或重写网络层；确需新增依赖时单独评估。

## 4. 信息架构与导航

### 4.1 登录前与登录后分离

```text
启动与账号恢复
├─ 未配置 / 配置无效
├─ 学校登录 / 重新验证 / 恢复失败
├─ 手机登记与本机身份确认
└─ 主界面
   ├─ 会话
   │  ├─ 电脑筛选与会话目录
   │  ├─ 已访问会话 / 需要处理
   │  ├─ 聊天
   │  │  ├─ 会话详情与发送记录
   │  │  ├─ 工具审批详情
   │  │  ├─ 普通 / 计划 / 计时提问
   │  │  └─ 附件与导出文件
   │  └─ 创建会话
   ├─ 电脑
   │  ├─ 已授权电脑与运行环境
   │  ├─ 电脑详情
   │  └─ 绑定流程
   └─ 设置
      ├─ 学校账号与手机登记
      ├─ 通知通道
      ├─ 应用更新
      ├─ 外观与无障碍偏好
      └─ 关于与诊断
```

### 4.2 导航规则

1. 默认进入“会话”；用户切换入口后，本次前台使用保留当前入口和安全的筛选状态。
2. 底部导航用于主入口，聊天与完整审批属于下一级页面，不继续挤占聊天底部空间。
3. 普通返回优先关闭键盘，再关闭面板，最后退出当前页面；系统返回与页面返回遵循相同业务收尾规则。系统身份确认、文件选择和安装页面遵循平台返回行为，回调仍由原操作生命周期接收。
4. 从电脑进入会话列表，返回对应电脑上下文；从最近会话进入聊天，返回原筛选和阅读列表位置。
5. 通知打开指定资源时，继续使用已知会话的最小授权路径；不能先要求获得更广目录权限。
6. 暂时授权上下文退出后清理；按原入口返回提醒或对应页面，不回落到其他账号或同名会话。
7. 未提交审批、绑定、问题、创建选择和身份确认操作在离开时执行现有失效逻辑。
8. 主导航不能让多个隐藏页面各自保留实时连接；首期沿用一个当前前台会话阅读上下文。
9. 返回位置只保存稳定定位键和偏移等展示信息；恢复前重新核验资源和消息是否仍可访问。
10. 退出账号、撤权及资源上下文变化时，原导航栈和页面事件按原有代次规则退役。

### 4.3 电脑与运行环境的表达

“电脑”用于产品导航，但授权和操作继续定位到确定的 `runtime_id`。同一物理电脑下的不同运行环境可以分组展示，子项仍显示可区分的 profile 信息；不能把多个运行环境合并成一个可互换的授权主体。

## 5. 视觉系统与组件规范

### 5.1 颜色与层级

- 继续以现有 `#3F51B5` 靛蓝作为浅色主操作色，并保留独立的深色映射。
- 背景、普通表面、抬升表面、边框、主文字和辅助文字使用语义 token。
- 正常在线状态保持低干扰；需处理、处理中、失败和权限失效分别有文字与图形提示。
- 红色用于错误或危险操作，不用来标记普通离线；离线优先中性色，重连与需核对使用适当强调。
- 同一页保持一个主要提交动作；刷新、查看详情、取消、移除记录等使用次级层级。
- 卡片用于确有边界的内容组；连续目录优先使用列表与分隔线。

### 5.2 基础尺寸

以下为首轮设计值；通过窄屏和大字体验证后调整，不能作为截断内容的理由。

| 项目 | 建议值或规则 |
| --- | --- |
| 页面左右边距 | 手机通常 16dp；完整审阅可按内容使用 16–24dp |
| 间距序列 | 4 / 8 / 12 / 16 / 24 / 32dp |
| 普通列表项 | 最小 64dp，随副标题和字体增长 |
| 图标可见尺寸 | 常用 20–24dp；点击区域至少 48 × 48dp |
| 标题栏 | 普通字号以约 64dp 为起点；大字布局允许调整，不强制裁切 |
| 输入组件主体 | 无附件、无异常时 100–128dp 为起点；安全区独立处理 |
| 内容圆角 | 内容组约 12–16dp；紧凑状态与代码块另设较小圆角 |
| 页面标题 | 20–24sp |
| 列表标题 | 16–18sp |
| 正文 | 16sp 为主，行高约 22–26sp |
| 辅助说明 | 通常 13–14sp；必须被理解的信息不降为过小字号 |
| 代码与指纹 | 等宽字体，支持复制及完整阅读，不按视觉长度改写实际值 |

### 5.3 明暗主题、窗口与无障碍

- 建立文字、边框、选中、聚焦、禁用和按压状态的明暗成对规范。
- 普通正文与背景对比度以至少 4.5:1 为目标；关键图标和控件边界以至少 3:1 为目标。
- 图标按钮设置用途明确的语义标签，选中、展开、禁用和加载状态可被辅助服务识别。
- 重要错误不只通过颜色表达；禁用动作附近给出具体原因和可执行的下一步。
- 输入、面板和固定操作区统一处理系统栏与 IME 留白，避免双重 padding 和最后一条内容被遮挡。
- 优先覆盖 320 / 360 / 411dp 手机宽度、横屏与 2.0 字体缩放。
- 大屏是否双栏由可用窗口宽度决定；以约 600dp、840dp 作为首轮布局分档评估点，不只判断设备型号。
- 窄窗口采用单栏；足够宽时可采用左侧会话目录、右侧聊天，业务连接仍遵守当前会话所有权。
- 减少动态效果的系统设置生效；连接和流式状态不依赖持续闪烁才能识别。

## 6. 页面与关键流程设计

### 6.1 登录、恢复与手机登记

**目标：** 用户知道当前步骤、下一步以及是否需要再次操作。

- 使用“学校账号 → 登记手机 → 进入会话”的简短进度表达；只在引导流程出现。
- 登录页提供单一登录主动作，账号来源和组织信息可查看，不把完整配置地址当主要文案。
- 未配置时明确显示原因和管理员处理路径；不把不可点击的等待按钮作为唯一可见反馈。
- 设备名称字段、登记说明和身份确认各有清晰位置；不改变平台密钥和生物识别要求。
- 恢复失败、重新验证、登记结果不明分别呈现，不统一成“登录失败”。
- 已完成登记后不在日常首页保留大号成功卡片；登记信息进入设置。
- 本地展示状态留在独立的演示或测试宿主，不向正式登录流程注入已认证状态。

**验收：** 不配置学校服务也能用夹具覆盖页面；正常安装包保持原来的配置与登录约束。

### 6.2 会话首页与目录

**首屏顺序：** 页面标题及新建入口、电脑筛选、需处理提示、会话列表。

| 元素 | 呈现规则 |
| --- | --- |
| 标题 | “会话”；账号与设备说明移至设置 |
| 电脑筛选 | 默认当前范围，支持进入电脑分组；没有全量索引时明确范围 |
| 列表主标题 | 优先使用受信任务标题；字段未具备时使用可靠标签与短 ID 兜底 |
| 副标题 | 当前获权的电脑、工作区或运行环境标签 |
| 时间 | 使用已知的更新时间；不能称为尚未提供的“最后回复时间” |
| 状态 | 运行中、可继续、已归档、电脑离线等已有确定状态 |
| 进入动作 | 整行点击；原访问检查继续执行 |
| 更多操作 | 提供可发现的菜单入口；长按和滑动只是辅助方式 |

- 不在每行重复放置“读取”“刷新”“创建”等多个通栏按钮。
- 初次加载、局部电脑失败、没有会话、无访问权、全体离线分别设计。
- 一台电脑查询失败不把其他电脑的有效结果清空；对未知状态保持诚实标记。
- 全量目录能力就绪前，先使用电脑分组或当前电脑列表；避免启动时逐一读取全部会话正文。
- 搜索首期只作用于已获得、当前可展示的索引，并说明范围；不能显示已撤权缓存的命中。
- 归档操作仍遵循原命令协议和显式确认，不增加默认“滑一下立即停止并归档”的行为。

**验收：** 已展示会话一次点击可发起打开；列表位置和筛选在安全范围内可恢复；目录只读授权不会启用正文读取或发送。

### 6.3 电脑列表与详情

- 按电脑与运行环境展示：名称、连接状态、最近一次可靠观察时间、可执行动作。
- 在线状态只能来自明确支持该事实的数据；没有当前在线来源时显示“状态待核对”。
- 列表以“打开会话”为常见操作；创建、绑定和详情按实际权限出现。
- 版本、完整 UUID、组织、profile 和公开密钥信息进入详情，不在每行重复展开。
- 首次没有电脑时提供绑定引导；已有电脑离线时提供诊断说明和已获权历史入口，不回到首次安装流程。
- 同名电脑必须通过组织、运行环境等可靠辅助信息区分。

### 6.4 聊天阅读

建议呈现层级：

```text
返回    会话名称                         更多
        电脑 / 工作区 · 当前连接状态
──────────────────────────────────────────
消息正文：用户、助手、工具摘要、文件引用
历史加载提示 / 局部错误
                          回到底部 / 新消息
──────────────────────────────────────────
需要处理的请求入口（存在时）
紧凑输入组件
```

1. 首次打开并完成当前快照后，默认定位当前窗口最新内容；返回同一会话时优先恢复安全的阅读锚点。
2. 用户位于底部时跟随实时增量；主动阅读历史后停止跟随，直到用户回到底部。
3. 使用稳定消息键和锚点偏移，避免历史前插、增量合并或工具折叠造成跳动。
4. 顶部接近历史边界时有界加载；同一时刻沿用现有单个相关分页请求，达到窗口上限后保留明确入口和说明。
5. 连接故障显示短提示，必要时展开恢复操作；普通健康状态不再使用大块正文卡片。
6. 支持标题、列表、引用、代码块和复制；消息显示仍来自项目的明确会话投影。
7. Markdown 不自动执行 HTML、脚本、命令或任意应用 intent；外部链接使用明确的用户操作和目标展示。
8. 不为了渲染图片自动请求正文中的任意远程资源；媒体能力按本项目授权文件机制另行设计。
9. 思考过程保留显式展开；工具已完成过程可紧凑呈现，详情和失败原因仍可打开。
10. 当前待审批、待答复及结果不明的状态不能因“压缩工具输出”而失去入口。
11. 发送记录与原生消息继续分离，不能通过相同文本猜测并合并一条已发消息。
12. 归档、文件、导出、诊断和完整发送记录转移到会话详情或按需面板。

**验收：** 上翻时的新消息不抢滚动位置；分页前插后原可见消息位置稳定；新订阅快照不能复活旧交互表单。

### 6.5 紧凑输入组件与发送状态

- 输入框、附件按钮和发送按钮形成一个清晰操作组。
- “排队发送 / 补充当前任务”使用紧凑选择入口，当前模式始终可辨认；能力不具备时说明原因。
- 多行输入自适应增高，到约定上限后在输入框内部滚动；不压缩到看不见提交动作。
- 普通说明按需展开；离线、输入不合法、附件不就绪和存储失败等必须被理解的提示保留。
- 附件使用紧凑标签或预览条，显示文件名、就绪状态和移除选择动作。
- “移出本次消息”与“删除本机记录”使用不同动作和文案。
- 在线提交继续先加密保存原意图，再按现有协议发送；未确认写入不能显示成功。
- 离线明确使用“保存待发送”；网络恢复后只核对状态，不自动转交原正文。
- 停止当前任务使用独立、易辨认的动作及原有确认；不能因发送按钮图标变化造成误中断。
- 未提交输入仍按现有生命周期清理，不使用明文偏好或 `rememberSaveable` 恢复敏感草稿。

| 真实状态 | 推荐短文案 | 可展开说明 |
| --- | --- | --- |
| 本机保存且未转交 | 待发送 | 仅保存在手机，尚未送往电脑 |
| 已开始一次转交、回执未明 | 待核对 | 先查询原请求，不能据此创建重复请求 |
| 中继已接收 | 中继已接收 | 尚未确认电脑持久保存 |
| 主机持久保存 | 电脑已保存 | 不表示 Agent 已处理 |
| Agent 入队 | 已入队 | 不表示任务完成 |
| 命令结算 | 按命令种类表达 | 中断、归档、创建、答案和消息分别映射，不统一成“任务成功” |
| 主机拒绝 | 未被接收 / 已拒绝 | 给出可理解原因，重试资格仍由原业务判断 |

**验收：** 点击发送只能调用现有协调器；原请求 ID、目标、正文和摘要不因 UI 重试改变；空白、Unicode 和附件约束保持。

### 6.6 工具审批详情

**页面结构：** 来源与有效期、完整动作阅读、核对进度、明确的决定动作、结果查询。

1. 页首展示当前电脑、会话和工具；完整身份绑定信息可以展开核对。
2. 工具、参数、工作区、资源按类型进行字段化展示；长字符串和代码保留完整阅读方式。
3. 任意 JSON 参数继续支持对象、数组、空值、数字、布尔值及未知参数键，不能只呈现预定义的几个常见字段。
4. 字段化展示来自当前经过验证的不可变审批上下文；签名仍使用该上下文的原规范字节和摘要。
5. 建立“上下文值 → 可见阅读片段 → 核对页”的覆盖关系。对象和数组的每个值都必须有可达的完整视图。
6. 不把摘要、语法高亮或折叠预览当作完整核对。未展开或未展示的参数不能计入已核对范围。
7. 保留逐页显式确认，再进行本次决定的独立确认。滚到末尾不自动代表同意。
8. 保留原始完整 JSON 的可切换阅读视图；切换表示不能绕过覆盖和确认规则。
9. 不可见方向、格式和控制字符按原有规则显式转义；显示转换不改变签名内容，分段不破坏 Unicode 字符。
10. 重要操作区保持易到达；固定按钮不得遮住最后一段参数。
11. “仅本次允许并确认身份”和“拒绝并确认身份”都是显式动作；拒绝不要求先确认允许所需的所有内容。
12. 本机身份确认、服务接收、电脑开始执行和最终结果分别显示，不合并为一次成功动画。
13. 超时、换代、撤权、另一设备决定、后台、离开页面或登录变化时，原核对状态与回调立即退役。
14. 回到页面需要新的在线详情和确认；历史原决定只能用于核对原结果，不能恢复成可执行批准。
15. 空资源列表明确说明没有额外绑定文件或仓库版本；不把未声明的资源描述为已冻结。

**验收：** 覆盖完整 128 KiB 上下文、超长尾部参数、数组嵌套、格式字符、页面切换、确认失效和真实平台签名回调；每个既有拒绝条件仍成立。

### 6.7 普通提问、计划确认与计时问题

- 聊天中先显示紧凑的“需要你答复”入口；用户明确打开后展示当前完整表单。
- 简短单题可在会话内展开；长问题和多题使用足够大的表单页面，避免多层嵌套滚动。
- 单选、多选和自由文本分别呈现；选项描述在标签旁，提交前不给用户代选。
- 计划确认完整展示计划详情后，才允许选择继续；计划答复和工具审批在标题、动作及结果上区分。
- 点击查看摘要、收到通知或切换主导航，不自动申请计时所有权，也不自动提交答案。
- 计时只使用当前原生状态及已有时间边界；本地倒计时归零不自行推断任务已经继续。
- `continued` 明确显示“作为后续答复发送”，不会再次完成旧问题。
- 关闭表单只执行现有 claim/release 生命周期，不暗示已取消电脑上的问题。
- 已有未明或已接收答案时，优先核对原答案，不生成另一条答案意图。
- 未提交选项、自由文本和计划确认不进入保存实例状态；已有加密原答案记录保留原对账用途。

### 6.8 会话附件、文件导出与保存

- 输入区“＋”提供上传入口；会话详情提供文件与导出入口。
- 文件面板按“本次选择、上传记录、导出来源、导出记录”区分，避免把四种状态混成一个列表。
- 每行展示文件名、可理解的大小、状态和一个主要下一步；详细摘要及原请求信息按需查看。
- 上传依次区分本机准备、上传、安全检查、等待电脑、电脑暂存及绑定原消息；检查通过不等于可发送。
- 只在当前状态允许时勾选加入消息；点击发送时仍由现有协调器重新核验。
- 导出来源只浏览已授权会话附件和工作区引用；不能由 UI 拼接绝对路径或请求任意文件。
- 导出区分准备、电脑上传、检查、可保存、下载校验、目标文档回读和最终保存。
- 保存成功继续以现有完整校验为准；取消或清理失败时明确提示不完整文档状态。
- 文件选择器、保存位置和权限回调继续绑定原账号、资源、操作代次和一次性令牌。
- 页面收纳不延长传输生命周期：离开或后台后的取消与清理由现有流程执行。

**验收：** 面板关闭、账号切换、迟到 URI、未就绪附件、重复回调、保存取消与清理失败都不绕过原流程。

### 6.9 电脑绑定

第一批保留现有协议，拆成“输入申请 → 核对电脑 → 等待确认 → 查看结果”。

- 输入页解释如何在电脑上取得申请编号和绑定码；字段支持粘贴与就地校验。
- 核对页突出组织、电脑、运行环境、工作区、有效期和完整安装密钥指纹。
- 指纹按等宽分组完整显示，可复制；不能用省略号或短指纹替代确认依据。
- 手机确认、电脑确认和当前授权目录三个事实分别展示；手机已确认不代表完成绑定。
- 结果不明时保留公开申请编号与查询入口，避免再次展示为一张新的确认表单。
- 绑定码不进入日志、URL、保存实例状态或剪贴板自动写入；后台和离开继续清理。
- 扫码增强另行定义版本化载荷、长度限制、组织与过期校验；解析成功只进入核对步骤。
- 扫码方案需覆盖无 Google 服务的目标设备，并保留手工输入路径。

### 6.10 创建会话

- 通过“电脑 → 工作区 → 助手配置”组织选择，当前已确定的电脑可直接作为上下文。
- 使用可搜索或分组的选择列表，数量较少时采用简单选择器；不在空列表中显示不可解释的禁用主按钮。
- 工作区与配置只来自当前运行环境已核验、已授权的选项。
- 选择为空、电脑离线、权限不足和选项失效分别解释。
- 不从工作区名称推导本机路径，不在手机展示或编辑模型凭据。
- 未提交选择仍只在当前流程内存中存在；运行代次改变后要求重新选择。
- 有未完成核对的创建请求时，清楚展示“先核对原请求”和“明确创建另一个请求”的区别。
- 成功依据原请求权威结算，打开前重新核验目录和读取权限；不插入虚构会话行。

### 6.11 待处理入口、通知与设置

- 会话首页的“需要处理”来自当前可验证的审批和问题引用；推送配置只影响后台提醒能力。
- 当前只有已知资源时显示“当前已同步会话中的待处理项”，不使用“全部已处理”等全量结论。
- 打开引用重新读取当前状态；已经结束的请求显示结果或失效说明，不恢复旧表单。
- 未读提示可随阅读清除，待处理计数只能随对应请求状态更新；两者分开建模。
- 通知设置只管理系统权限、可用通道、登记、续期和停用；未配置推送不阻挡前台答复。
- 锁屏和系统通知继续隐藏正文、完整参数及主机别名。
- 设置按账号与设备、通知、外观、更新、关于组织；退出与日常导航分开。
- 应用更新依次呈现检查、下载校验、系统安装确认和结果核对，不把下载完成称为更新完成。
- 修改外观偏好可以持久化；外观偏好不得夹带当前账号凭据、命令正文或交互上下文。

## 7. 状态、权限与生命周期矩阵

### 7.1 页面状态

| 状态 | 主内容 | 可用操作 | 必须避免的表达 |
| --- | --- | --- | --- |
| 初次加载 | 有界占位与当前步骤 | 返回、必要时取消 | 把未取得结果显示成空目录 |
| 已连接且可读写 | 当前快照与短连接状态 | 按已核验能力发送和处理 | 用连接成功代替消息保存或执行成功 |
| 仅目录授权 | 已授权目录 | 浏览目录、返回 | 启用正文读取或命令发送 |
| 可读但不可写 | 当前获权内容 | 阅读、复制允许展示内容 | 仅以“禁用发送”掩盖真正的权限原因 |
| 电脑离线、缓存仍可获权读取 | 已确认历史及缓存标识 | 阅读；符合原规则时保存待发送 | 声称任务仍在运行或展示可执行旧审批 |
| 离线且无法取得有效读取权 | 状态与恢复说明 | 重试、重新验证 | 只因文件存在就解密并展示历史 |
| 网络中断 | 当前允许展示的内容与恢复提示 | 查询、重试、按规则保存本地意图 | 自动重复转交已尝试的请求 |
| 权限撤销 / 资源换代 | 退役后的说明与安全返回 | 核对当前权限 | 保留旧正文、旧确认或旧签名回调 |
| 结果不明 | 原请求引用与已知事实 | 查询原状态 | 用“失败”引导无条件创建重复操作 |
| 历史为空 | 已确认的空状态 | 按权限创建或发送 | 与离线没有缓存混淆 |

### 7.2 状态保存分类

| 分类 | 例子 | 保存与恢复规则 |
| --- | --- | --- |
| 非敏感偏好 | 主题、字号偏好、纯外观布局 | 可持久化，与凭据和正文分开 |
| 资源展示定位 | 电脑筛选、列表偏移、消息锚点 | 按账号隔离；只保存必要标识，恢复前重验当前权限 |
| 已确认历史 | 已持久化的原生消息 | 沿用加密缓存、有效期、容量与当前授权检查 |
| 持久操作记录 | 原消息、原答案、原创建、原审批证明 | 沿用现有加密日志；重开只用于原请求恢复与对账 |
| 未提交交互 | 草稿、问题选项、创建选择、绑定码 | 不新增进程恢复；沿用当前内存生命周期 |
| 临时授权与确认 | 审批 handle、已核对页、勾选同意、生物识别操作 | 不持久化；后台、离开、失效或身份变化时退役 |

主导航、面板和大屏适配必须使用同一组分类规则，不能因为组件进入返回栈就扩大持有期限。

## 8. 数据来源与协议增强设计

### 8.1 展示数据来源登记

| 展示字段 | 当前来源或缺口 | 首轮决策 |
| --- | --- | --- |
| 电脑别名、运行环境、授权角色 | 当前 runtime 目录及访问元数据 | 复用并核验，不另建 UI 授权缓存 |
| 会话 ID、工作区 ID、状态、更新时间 | 当前 `SessionDirectoryEntry` | 直接用于列表基础展示 |
| 工作区标签 | 当前被允许的公开配置或明确受权元数据 | 有来源才显示，不能从本地路径猜测 |
| 任务标题 | 当前目录缺少该字段 | 本地别名或后续协议增强；标明别名的本机范围 |
| 最后消息摘要 | 当前目录缺少该字段 | 首轮不抓取全部正文来填摘要 |
| 未读数量 | 缺少明确的已读与计数合同 | 首轮不伪造数量；后续定义基于持久位置的规则 |
| 是否有待处理请求 | 当前会话审批与问题状态；部分提醒引用 | 仅表述当前获权、已验证范围 |
| 是否在线 | 明确的当前连接或服务端 presence 能力 | 没有来源时显示未知，不根据更新时间推断 |

### 8.2 增强字段的实施前提

1. 分别写明字段生产者、授权范围、公开程度、长度、编码、更新时间和删除方式。
2. 会话标题、别名和摘要按账号、组织及资源隔离；摘要可能包含正文，应单独评审持久化与保留范围。
3. 现有解析器包含严格字段校验，不能直接在旧帧中塞入任意新字段。先定义明确的协商、版本或兼容扩展位置。
4. 共享合同、Host 生产、Go 验证与投影、Kotlin 解析、演示夹具和兼容测试一起更新。
5. 目录扩展不授予正文权限；摘要的可见范围必须单独说清，不能借目录枚举扩大读取。
6. 本地别名若实施，放在账号隔离的合适存储中，具备撤权、清除账号与资源删除处理；不使用全局明文资源映射。
7. 聚合使用有界分页、并发和取消机制；不为展示首页保留所有运行环境及会话的实时订阅。
8. 数据缺失、部分资源失败与“全量为空”分开表达，不用局部索引证明没有待办。

协议增强未验收时，基础界面继续通过短 ID、明确状态与现有目录工作，不阻塞第一批交付。

### 9.2 状态与事件边界

- 先提取展示模型与纯映射函数，明确“业务事实”和“排版状态”。
- Screen 通过事件调用现有 ViewModel / 协调器，Composable 不直接发 HTTP、签名或写数据库。
- 滚动锚点、面板展开和筛选可以属于 UI；当前授权、原意图、决定摘要和是否允许重试继续由业务层拥有。
- 列表模型使用稳定键；权限、账号和导航代次变化能使旧异步结果失效。
- 一次拆一个区域，保持可运行，避免同时重写登录控制器、网络连接和全部页面。
- 若采用新的导航依赖，先验证生命周期、返回栈和敏感状态清理，再决定是否引入；不要求为了本计划升级整体技术栈。
- 不新增无界消息、目录或 Markdown 渲染缓存；沿用现有历史窗口和容量边界。

## 10. 本地展示与交互夹具

### 10.1 展示原则

- 展示数据独立于真实学校账号、模型与生产推送配置。

### 12.3 运行与记录方式

只变更文档时检查文档结构、链接和范围即可。实施阶段按实际改动运行定向测试，再运行阶段出口要求的检查，不为排版改动反复运行无关系统压测。

Android 基础检查在 `android/` 下运行：

```sh
./gradlew check :app:assembleDebug :app:assembleDebugAndroidTest
```

平台用例仅在明确选定、已准备好的专用测试设备运行，并按用例需要显式启用本项目的夹具参数：

```sh
ANDROID_SERIAL='<专用测试设备序列号>' ./gradlew :app:connectedDebugAndroidTest
```

发生共享合同或跨端行为变化时，再补充对应的合同检查、Host、Go、Kotlin 与本机 DSH 联调。真实运行时测试执行前记录本机 `dsh --version`，使用项目当前验证的发行版，不将本地界面样例当作原生链路通过。

测试记录至少包含提交、构建类型、设备、系统、分辨率与密度、字体缩放、主题、场景、命令、开始与结束状态及结果。设备测试不占用或重置日常预览实例，不清理全局 adb，不发布或推送任何产物。

## 13. 可用性与性能验收

### 13.1 核心任务走查

对下列任务使用相同样例和初始状态，比较操作步骤、错误选择、找不到入口及完成时间：

1. 找到指定电脑的已有会话并阅读最后一条消息。
2. 向该会话排队发送文字，再找到其准确发送状态。
3. 阅读一段历史，期间接收新消息，再回到最新位置。
4. 核对一个长参数工具调用，拒绝一次并查看结果。
5. 回答一个多题表单，关闭另一个计时问题而不答复。
6. 上传附件并理解“检查通过”和“电脑已暂存”的区别。
7. 导出并保存文件，取消一次保存并找到相关提示。

目标是减少非必要步骤与误解；不以减少完整审批核对步骤作为效率收益。

### 13.2 性能目标与测量

- 将屏幕进入至首个可操作本地内容、目录加载、正文首屏和实时更新分别测量，网络时间单独记录。
- 在确定的 60Hz 测试设备上，以 16.7ms 帧预算分析滚动与输入；其他刷新率按实际预算记录。
- 覆盖长历史、流式增量、多代码块和长审批上下文，记录慢帧、长任务与峰值内存。
- 关注状态条和单条增量更新是否引发整页重组；用实际采样定位，不依靠组件数量猜测。
- 主线程不进行数据库读写、网络、签名或大规模 Markdown / 审批投影计算。
- 不为优化首屏突破已有历史记录、命令、文件及审批内存预算。
- 新布局不增加无界重连、查询和分页循环；网络请求数与连接数列入回归观察。

性能报告只对指定设备、构建和数据场景有效。调试包、模拟器和物理设备分别报告，不从截图或一次流畅操作推导性能结论。

## 14. 提交、回退与交付管理

### 14.1 建议提交粒度

| 阶段 | 建议 commit message | 内容边界 |
| --- | --- | --- |
| U0 | `docs(android): define UI and UX implementation plan` | 独立计划、范围和验收 |
| U1 | `feat(android): add task-focused app navigation` | 导航壳、基础组件与设置迁移 |
| U2 | `feat(android): improve session browsing and chat reading` | 目录、标题、正文、锚点与分页 |
| U3 | `feat(android): compact message input and delivery feedback` | 输入、模式、附件选择与原请求状态 |
| U4 审批 | `feat(android): present complete approval actions by field` | 完整阅读、核对覆盖与确认 |
| U4 交互与文件 | `feat(android): streamline questions and session files` | 提问、文件及流程反馈 |
| U5 | `feat(protocol): add scoped session presentation metadata` | 仅在纳入本次范围时提交完整跨端合同变更 |
| U6 | `test(android): validate responsive session workflows` | 实际新增的关键交互与适配回归 |

一个阶段可以拆成多个可审阅提交。提交说明描述实际变更和验证，不提前声称整个阶段通过；只暂存本阶段文件，不包含其他并行任务或根目录 `PLAN.md`。提交以实际实现和相应验收为依据，应用发布与部署另按其交付流程处理。

### 14.2 回退约束

- 首轮 UI 变更优先保持现有存储和网络合同，使页面可独立回退。
- 新增持久数据时提供非破坏迁移、清理策略及旧版本兼容说明。
- 回退页面不得抹去已提交的原请求、审批证明和未明结果记录。
- 原始完整审批视图可保留为逐步替换期间的完整阅读入口；两种视图共享相同业务约束。
- 演示数据与应用运行数据分离；回退不触碰现有账号、密钥或预览模拟器数据。

## 15. 风险与处理决策

| 风险 | 处理方式 | 阶段 |
| --- | --- | --- |
| 首页美化依赖尚不存在的字段 | 先实现真实可用的兜底展示，字段增强独立验收 | U0、U2、U5 |
| 聚合导致权限扩大或连接过多 | 限定当前获权资源、有界查询，避免全会话订阅 | U2、U5 |
| 返回栈保留了临时授权和确认 | 明确页面退役点，业务操作不依赖 Composable 是否仍在内存 | U1、U4 |
| 紧凑控件降低可达性 | 保持点击区域、明确标签、大字增高和可滚动内容 | U1–U6 |
| 实时更新与分页造成跳动 | 稳定键、锚点恢复、底部跟随门槛和定向交互测试 | U2 |
| 结构化审阅遗漏未知参数 | 通用完整 JSON 值投影、覆盖映射和尾部参数用例 | U4 |
| 简短文案掩盖可靠性差异 | 保留状态模型，短文案可展开查看原请求事实 | U3、U4 |
| 通知入口要求不必要的目录权限 | 保持已知资源最小授权路径和临时上下文清理 | U1、U4 |
| 界面截图被当作真实业务通过 | 独立记录合成展示、平台、跨端与物理设备证据 | U0–U6 |
| 学校与厂商配置未就绪 | 继续本地夹具，不在正式包植入兜底身份或假推送能力 | 全程 |
