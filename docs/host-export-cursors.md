# Host 导出目录游标的并发与关闭

`ExportCatalog` 在首次分页调用原生目录 I/O 之前预留游标名额。已保存、正在分页和正在关闭的
游标共同遵守八项上限，不再等首次分页返回才计数。并发请求不能同时看到旧的 map 数量并越过预算。
同一 continuation 仍只能由一个请求推进，成功后生成新的随机 token，旧 token 失效。

每个游标有独立取消信号。过期、失去原目录或 catalog 关闭会将其退休；正在执行的分页先取消，
实际返回后再接收并关闭句柄。名额在关闭 Promise 结束后归还，未返回的底层 I/O 仍占预算。
根目录查询、分页、准备和媒体验证也受八个在途调用上限约束，关闭会等待这些调用及已退休游标的收尾。

## 身份与晚返回结果

每次调用固定原用户、设备、key/grant version、workspace 范围和期限。
await 前后继续核对原 scope，不能因调用方在等待期间修改对象而以另一身份发布目录或条目。
分页的原目录必须仍存在，关闭或取消后晚返回的 reader 会被接收清理，不能发布新的 continuation。

关闭先同步停止准入、清空公开索引并取消生命周期，再等待在途工作和所有目录句柄关闭。
重复 close 复用同一结果；来源关闭错误不跳过其他清理，最终以固定错误报告，不暴露路径。
这不改变不透明 ID 协议，也不能强制结束不响应取消的文件系统调用。

## 定向验证

实际 npm DSH `0.2.1-rc.5` Loader 与 Linux procfs 夹具验证：保存七个目录游标后，
第八个在真实分页返回前暂停，第九个请求立即拒绝，没有多开句柄；关闭后描述符归零。
另覆盖首次 reader 晚返回时关闭等待、根元数据晚返回，以及分页期间设备身份变化不能发布结果。
夹具只创建少量空文件和有限目录句柄，不是吞吐或大负载测试。

集中运行 14 项上述及原有目录 scope、原生会话附件／图片和 Relay 导出用例，全部通过，无跳过；
TypeScript 检查通过。
没有全量回归、Go、Android、Windows／Wine、真机或学校身份测试。
