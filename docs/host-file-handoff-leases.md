# Host 文件交接的期限约束

`RelayFiles` 为每个交接保存独立的 `FileHandoffLease`，同时使用墙钟和单调时钟。
五秒续租期限、最初五分钟硬期限和原有一百毫秒余量都在使用 receipt 时核对；
观察到到期、时钟倒退或无效时钟后，该交接永久失效，后来回复或时钟恢复都不能重新开放。

offer 只接受不超过五秒加五百毫秒时差的租约，以及不超过五分钟加三十秒时差的硬期限。
本机单调时钟预算仍分别限制为五秒和五分钟，时差余量不会延长本机持有权限的时间。
续租必须在原租约仍有效时收到，不能改变原始硬到期；即使墙钟暂停，硬期限也不会被逐次续租推迟。
这些约束与现有 Go 交接期限一致，没有修改文件协议或延长服务端权限。

## 迟到回复与读取

原有 `file.renew`、`file.staged` 和 `file.release` 应答等待均为 2.5 秒。
现在在处理回复时也核对墙钟／单调时钟，不依赖每 250 毫秒一次的清理 timer。
续租迟到或 staged 确认迟到会终结相应交接并退休未使用 receipt；release 回执迟到只清理等待记录。
已过期的 receipt 不能先变成不可用，再因稍后到达的续租重新可用。

构造读取证明前、异步签名后、收到响应头后，以及读取每块 body 前后都检查交接权限。
过期后不开始新的 GET，也不把新到达的 body 块送进原生附件流。错误会取消 reader 和交接，
服务端仍按既有元数据及扫描规则核对，不能依靠 Host 检查替代服务端授权。

同一文件若仍符合当前授权，可由服务端重新发送全新 handoff，重新下载并生成新 receipt。
这个恢复路径不会使用旧 ticket 或旧回调。回收 receipt 不删除已经持久准入的 DSH 附件对象，
也不撤销已经进入原生消息队列的文件事实。

## 验证范围

集中定向用例使用可注入的内部时钟，不修改系统时间或缩短生产期限。
纯期限用例覆盖墙钟暂停、倒退、单调时钟耗尽、硬期限、畸形／越界期限及不可复活状态。
实际精确锁定的 npm DSH `0.2.1-rc.5` Loader 用例检查迟到续租与确认不能开放 receipt、旧 receipt 被退休后可重新交接、
签名结束后失效不发 GET，以及过期 body 的零字节准入。

本批集中运行 13 项文件交接相关 Host 用例和 TypeScript 检查，全部通过，无跳过；没有全量 Go／Host 回归、
Android、Windows／Wine、真机、大负载或生产对象服务验证。
